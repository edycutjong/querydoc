Solution

A model proposes. Code decides.

Executes both, compares rows, times pairs.

  1. original runs twice — deterministic?
  2. same columns and types
  3. 0 rows differ (or equal row hash)
  4. ≥ 1.2×, saving ≥ 1,782.9 ms, most pairs won

Diagnoser + Rewriter: Nemotron 3 Ultra · Verifier + Orchestrator: TypeScriptv0.1.0 · code b05f6f7 · 03 / 11
Two agents use the model, two are plain code. The Verifier has no model at all: it runs the queries on the engine. A refusal goes back to the Rewriter as a reason code; the latest one also carries the Verifier's detail and the differing row.

It keeps the wrong answers.

We keep the losing rewrites on the report too, with the row that proves them wrong. Honestly: the retry loop did not learn here; all three attempts changed the rows. What saved it was the gate, not the model.
