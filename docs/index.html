Method · three agents and an orchestrator, one rule

A model proposes. Code decides.

Nemotron writes the diagnosis and the rewrite. The verdict, every number and every timing come from code that executes both queries on Zetaris.

code · no model

Verifier

It runs the original and the rewrite on the engine and refuses anything it cannot measure.

  1. determinism pre-check — the original runs twicesame rows
  2. schema check — column names and typesequal
  3. row diff, or an engine-side row hash above the cap0 rows differ
  4. alternating paired timing — ≥ 1.2×, most pairs wonsaving ≥ 1,782.9 ms (Zetaris noise floor)
xxhash64 · EXPLAIN FORMATTED · run_sql

model

Diagnoser

Reads the Spark plan, a pattern detector and SQL-aggregate key facts.

Rewriter

One rewrite per hypothesis. It sees every earlier refusal as a reason code, and the latest one with the Verifier's detail and the differing row.

Playbook

Refusals, and outcomes a human approves, go into the playbook. A candidate already refused for the same original result is answered from the ledger, not run again.

Questions a judge would ask

Before you sign off.

Does a model decide whether a rewrite ships?

No. The Verifier is deterministic code: it executes both queries, compares the rows and times alternating pairs. The model's text is labelled as model text in every report and never decides anything.

Is the 2.11× measured or estimated?

Measured: wall clock on the local Zetaris platform over JDBC, 10 alternating pairs, rows verified identical first. The p50s are 32,442.6 ms and 16,428 ms. It is one laptop and says nothing about a hosted deployment.

Can I run it without keys?

Yes. Sample mode runs DuckDB on a committed NYC TLC subset with recorded model answers, and all 447 tests run keyless. The sample pack has no ACCEPT: the accepted speedup is from live Zetaris only.

What is not shown live?

Meterless Nightshift. It is the default provider in code with 16 mock-runtime tests, but it was never run against a live runtime; every recorded run used direct NVIDIA NIM, and every recorded trace with a model call names nim.

Will it change my database?

No. The guard admits one read-only statement per query; a rewrite cannot write or run a second statement. An accepted case is a candidate; when a human approves it, a patch file is written for them to review and apply.

Is "same rows" a proof?

No, and the report says so: the rewrite is identical on the current data and verified by execution — it is not a proof for all future data.
